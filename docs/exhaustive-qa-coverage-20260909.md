# Feature QA — September 9, 2026

**Acceptance remains incomplete.** The documented runs produced at least 278 physical photographs, corrected three reversed rendering controls and a G7 X color regression, and passed two physical Roll paging runs. The latest simulator core run passed 411 tests. The movable histogram and full settings/device matrix still need completed acceptance runs; the results below do not establish that every feature works.

## Implemented changes

- The histogram can be dragged, remembers its relative position, stays within measured camera controls, adapts to rotation, and offers reset and accessibility movement actions.
- Roll detail supports previous/next swipes, buttons and a frame counter. Zoomed drags pan; changing frames cancels stale image requests and keeps sharing tied to the active frame.
- The viewfinder supports horizontal look changes in library order and double-tap camera switching while preserving focus taps and pinch zoom.
- Removed the 120-identifier ownership truncation and 60-frame PhotoKit fetch limit, which otherwise hid older app-created photos. Ownership checks still exclude unrelated library photos.
- Corrected Highlights, Incandescent WB and Underwater WB directions; adjusted G7 X red/blue separation after the highlight correction. The renderer is `core-image-parametric-v11`.
- Fixed a collapsed Settings flash selector, increased the Pro Done target, and clamped camera-reported white-balance gains before front/back switching. These defects were found during acceptance; latest physical verification remains pending.
- Recipe editor help now explains preset-strength DR Auto and captured-balance White Priority/Custom modes. These are not scene metering or reference-white sampling.

These descriptions reflect source changes. Runtime scope is recorded separately below.

## Photograph and visual evidence

The physical catalog test made **128 separate sensor captures**, one per expected recipe in catalog order. All source and output hashes were unique; per-capture JSON, sizes and dimensions matched the session manifest. It retained 256 JPEGs plus 128 per-shot JSON attachments, with 3024×4032 normalized finished images. Capture/render elapsed time averaged 1.438 seconds (0.970–2.177), and the 207-second session recorded no camera runtime errors. Flash was off for all 128 shots.

The reviewer inspected all **11 physical contact sheets / 128 matched original-and-filtered pairs**, plus all **8 v11 fixture sheets / 128 catalog rows**. No gross broken render, unexpected monochrome leakage, wrong orientation or edge seam was seen at that scale. Three original-resolution attachments were opened, but the review tool displayed them downsampled to 1368×1824, so this was not a native-pixel inspection of every image.
