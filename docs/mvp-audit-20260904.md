# MVP source and release audit — 2026-09-04

The app has a coherent camera, recipe, import, review, and local Roll architecture. This sweep found concrete capture-state, zoom, save-error, rendering-context, cache, accessibility, and release-cleanup defects. Implementation was delegated during review. There is no source-confirmed P0. Public launch still requires fresh physical-device evidence and replacement store screenshots; passing simulator tests does not establish either.

This document records a read-only audit of production code and release tooling. The auditor did not run builds, change application source, mutate Git, upload an app, or operate the camera. Other agents are implementing and validating the findings concurrently. An item marked “patch reviewed” means its source change was inspected, not that physical behavior was verified. Source references below use the initial inspected tree unless explicitly identified as a new patch; lines may move as the changes are integrated.

Integrated source re-review: build 5 is present in both `project.yml` and the generated project, ignored fixture resource references are removed, and the thumbnail UIImage, gallery pan/reset, typed unavailable guidance, Reduce Motion, import pause, cache generation, and foreground idle-timer changes are present. Final simulator and hardware runs are owned by root and were not inferred from these source checks. The shared outer navigation/import busy policy now includes loading, import, capture, save, and review. A physical run exposed a SwiftUI publication warning; its traced source and remaining verification are recorded below.

## Remaining physical and product acceptance

1. Install the final built commit on the unlocked iPad. Record exact commit, configuration, bundle version/build, device model/OS, and result bundle. Repeat a focused camera pass on an iPhone with the relevant telephoto/flash hardware; an iPad cannot establish iPhone 5x behavior.
2. Verify first install and denied camera access, Settings recovery, foreground/background return, interruption recovery, tab round trips, and return after the 45-second warm window. Lock AE/AF, background the app, return, move between bright/dark and near/far subjects, and verify the published state agrees with actual focus/exposure behavior.
3. Capture G7X and representative Fuji color/mono recipes with flash Off/On where supported. Require review, retake, actual Photos save, saved-byte dimensions/orientation/recipe metadata, and matching Roll item. Exercise save denial and recovery without losing the review or duplicating a successful photo.
4. Test portrait/landscape/front/back, aspect-fill edge targets, tap focus at all corners, pinch and every advertised lens preset. Confirm the active optical constituent where the hardware exposes it.
5. Import portrait/landscape EXIF-oriented, wide-gamut, small, large, and invalid photos. Verify original framing, bounded-size disclosure, responsive controls, correct G7X portrait treatment, and save/share. Background/reactivate during a large import to check pause ownership and memory behavior.
6. Open populated Roll under full, limited, and add-only Photos access. Test iCloud delay/failure, thumbnail retry, zoom/pan/reset, share completion/cancel on iPad, delete confirmation, cache clear, and foreground refresh after external Photos deletion.
7. Visually inspect the same real photographs across all 36 looks at preview and exported size. Use neutral gray, varied skin tones, foliage, blue sky, high-contrast edges, bright specular highlights, low light, and actual direct flash. Slightly stronger grain/halation is acceptable, but preserve face detail, highlight shape, and distinct recipe identities. Keep G7X grain-free according to its existing compact-digital contract.
8. Measure cold first live frame, warm tab/retake return, sustained preview frame time, recipe switching, capture-to-review, import/export latency, memory peak, and thermals. A 30 fps preview has a 33.3 ms total-frame budget; isolated renderer timing alone is insufficient. Avoid broad cosmetic work until sustained preview behavior is acceptable.
9. Inspect large Dynamic Type, VoiceOver order/actions, Reduce Motion, landscape, iPad Split View, safe areas, and share popover placement. Capture fresh store images only after this pass.
10. Finish from a clean final commit: pinned project regeneration, required unit/UI/release gates, branch push and exact-head CI, signed archive/IPA provenance, and live deployment/readback if publishing. A pushed branch, local installation, TestFlight upload, and public App Store availability are distinct outcomes.

The desired G7X/Fuji feel is an aesthetic target. A comparative claim against flag7x or a vendor camera requires controlled same-scene examples and human assessment; neither code review nor a green test suite establishes that claim.
